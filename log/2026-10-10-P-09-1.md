## Done
- `card plan start <id>` in bin/card creates the card file for a row and prints its path. `Read` has the specification's path and `(row <id>: <heading>; <heading>)`, or `(row <id>)` for a row with no `spec` item. `Acceptance` has the `does` lines and `Out of scope` the `not` lines. `Touch` and `Tests` are empty. Nothing is committed or staged.
- The row is read through `outlines`, the reader of P-02, and is the first of that id in the order of the outline paths, as in `deck_table`. Its text goes to awk through the environment and is never evaluated.
- `cmd_new` is now the argument parsing only. `write_card` checks the four values and writes the file; `title_fault` and `depends_list` hold the title rules and the dependency list, so that `plan start` can check a row with them.
- It exits 1 for an id with no row, for an id with a card file in the working tree or on a base branch, for a row in an outline the reader has a finding for, and for a row whose title, size or dependencies a card cannot have. The message names the outline. A malformed id exits 2.
- `card help`, the synopsis of `card plan` and docs/reference.md list the command.
